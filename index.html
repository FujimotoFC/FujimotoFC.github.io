How the Developer Platform Works

Kubernetes · GitOps · policy-as-code
An Internal Developer Platform (IDP) I built to practice production-style platform engineering: developers ship by committing to Git, and the platform handles delivery and enforces standards automatically.

GitOps Delivery

  • Git is the source of truth — a git push is the deployment.
  • Argo CD watches the repos and reconciles the cluster to match.
  • No manual kubectl apply in the normal workflow.
  • Runs on Kubernetes (kind, v1.32).

Self-Healing

  • Manual changes to live resources are auto-reverted to match Git.
  • Prevents configuration drift between cluster and repo.
  • Verified by scaling a workload by hand and watching it snap back.

Security Guardrails

  • Kyverno enforces policy-as-code at admission.
  • Workloads without CPU/memory limits are rejected before creation.
  • Rolled out Audit → Enforce; scoped to application namespaces.
  • Golden-path service template keeps new services compliant by default.
